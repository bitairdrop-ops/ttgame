# Escalation Requests

Commands are run outside the sandbox if they are approved by the user, or match an existing rule that allows it to run unrestricted. The command string is split into independent command segments at shell control operators, including but not limited to:

- Pipes: |
- Logical operators: &&, ||

Each resulting segment is evaluated independently for sandbox restrictions and approval requirements.

Example:

git pull | tee output.txt

This is treated as two command segments:

["git", "pull"]

["tee", "output.txt"]

Commands that use more advanced shell features like redirection (>, >>, <), substitutions ($(...), ...), environment variables (FOO=bar), or wildcard patterns (*, ?) will not be evaluated against rules, to limit the scope of what an approved rule allows.

## [ASSISTANT]
微调专用模型的简要路径：

1. **确定任务**
   - 例如：客服问答、代码助手、游戏 NPC、交易监控总结、文案生成。
   - 先定义输入、输出、语气、不能做什么。

2. **选基础模型**
   - 中文/通用：Qwen、DeepSeek、Llama 系列。
   - 本地轻量：7B / 14B。
   - 云端或多卡：32B / 72B。
   - 起步建议：`Qwen2.5-7B` 或 `Qwen2.5-14B`。

3. **准备数据**
   - 格式通常是 instruction / input / output。
   - 例如：

```json
{
  "instruction": "根据交易数据生成风险摘要",
  "input": "Token A 24h 成交量上升 300%，前十持仓占比 62%",
  "output": "该项目短期热度上升，但持仓集中度偏高，需重点关注大户抛压。"
}
```

4. **清洗数据**
   - 删除重复、错误、低质量样本。
   - 统一语气、格式和边界规则。
   - 高质量 500-2000 条就能做出可感知变化。

5. **选择微调方式**
   - 推荐先用 **LoRA / QLoRA**。
   - 成本低，不需要全量训练。
   - 工具可用：LLaMA-Factory、Axolotl、Transformers + PEFT。

6. **训练**
   - 设置学习率、batch size、epoch。
   - 小模型可以单张 24GB GPU 起步。
   - 没本地 GPU 可用云 GPU。

7. **评估**
   - 准备一批未参与训练的测试问题。
   - 看准确性、格式稳定性、幻觉、拒答边界。
   - 和原始模型对比。

8. **部署**
   - 合并 LoRA 或加载 adapter。
   - 用 vLLM、Ollama、llama.cpp、TGI 部署成 API。
   - 接到你的 App、网页、Bot 或 Agent 系统。

最短路径是：

```text
选 Qwen/DeepSeek
→ 准备 1000 条高质量样本
→ 用 LLaMA-Factory 做 LoRA 微调
→ 用测试集对比原模型
→ 用 vLLM/Ollama 部署
```

不要一开始追求大数据量。专用模型最关键的是：**任务定义清楚 + 样本质量高 + 输出格式稳定**。

## [ASSISTANT]
DeepSeek 的核心架构可以理解为：**Transformer 底座 + MLA 注意力压缩 + MoE 专家网络 + 强化学习推理训练**。

以公开的 **DeepSeek-V3 / R1** 为例：

1. **底座还是 Transformer**
   - 和 GPT、Llama、Qwen 一样，基础结构仍是 Decoder-only Transformer。
   - 输入 token 后，经过多层注意力和前馈网络，预测下一个 token。

2. **用 MoE 扩大总参数，但降低单次计算**
   - DeepSeek-V3 是 MoE 架构，公开报告称总参数约 **671B**，但每个 token 只激活约 **37B** 参数。

主要优势：

1. **成本可控**
   - 外部 API 按 token 计费，规模起来后成本会很高。
   - 自主模型可以用自有 GPU、私有云或量化部署，把长期推理成本压下来。
   - 类似 DeepSeek 的价值之一，就是用 MoE、MLA、FP8 等方式降低训练和推理成本。

2. **数据安全**
   - 私有文档、代码、用户数据、交易策略、客服记录不用发给第三方。
   - 对金融、医疗、企业内部系统尤其重要。
   - 可以部署在本地、内网或私有云。

3. **能力可定制**
   - 通用模型什么都会一点，但不一定稳定符合你的业务。
   - 自主模型可以专门优化：
     - 固定输出格式
     - 专业领域知识
     - 品牌语气
     - 工作流规则
     - 风控边界
     - 特定工具调用方式

4. **产品体验稳定**
   - 不完全受外部 API 限流、涨价、模型下线、策略变化影响。
   - 可以自己决定上下文长度、响应速度、拒答规则、工具调用方式。
   - 对长期产品很关键。

5. **形成技术壁垒**
   - 如果你有独特数据，模型微调后会形成差异化能力。
   - 例如：
     - 链上交易监控模型
     - 游戏 NPC 行为模型
     - 私有代码库开发助手
     - 投研摘要模型
     - 客服转化模型

6. **更容易深度集成业务系统**
   - 自主模型可以和数据库、Agent、钱包、游戏引擎、内部工具深度绑定。
   - 不只是“聊天”，而是变成业务自动化核心。

7. **长期商业议价权**
   - 如果完全依赖一家模型 API，产品成本和能力边界都被对方控制。
   - 自主模型能让你在多个底座之间切换，也能保留自己的 adapter、数据和评估体系。

+ 私有部署

模型架构创新

2. **MiniMax-VL-01**
   - 视觉语言模型。

   - 推理模型，基于 MiniMax-Text-01 继续发展。

## [ASSISTANT]
算力中心和模型公司的合作，本质是：

```text
算力中心提供 GPU / 网络 / 机房 / 运维
模型公司提供模型算法 / 数据 / 训练任务 / API 产品
双方一起把算力变成模型能力和商业收入
```

常见合作逻辑有几种。

**1. 租算力**
模型公司直接租 GPU 集群。

```text
模型公司付费
→ 算力中心提供 H100 / H200 / A100 / 昇腾等资源
→ 模型公司训练或推理
```

这是最简单模式。  
算力中心赚租金，模型公司获得训练/推理资源。

**2. 云服务分成**
算力中心或云厂商托管模型公司的模型，然后对外卖 API。

```text
模型公司提供模型
→ 云厂商部署到平台
→ 企业客户调用 API
→ 双方按收入分成
```

类似：

```text
模型即服务 MaaS
```

模型公司拿模型授权/API分成，算力中心拿基础设施和平台收入。

**3. 联合训练**
算力中心出 GPU，模型公司出算法和团队，双方共同训练模型。

```text
算力中心：GPU + 网络 + 机房
模型公司：模型架构 + 数据工程 + 训练代码
产出：联合模型 / 行业模型 / 私有模型
```

这种适合地方智算中心、产业园、国资云、行业集团。

**4. 私有化部署**
企业客户想用大模型，但数据不能出内网。算力中心负责部署环境，模型公司负责模型和适配。

```text
企业客户
→ 购买私有大模型方案
→ 算力中心提供本地/专有云算力
→ 模型公司提供模型、微调、RAG、评估
```

收入可能包括：

```text
部署费 + 授权费 + 运维费 + GPU 租赁费
```

**5. 推理托管**
训练不一定在算力中心做，但模型上线后的推理服务放在算力中心。

```text
模型权重
→ 算力中心托管推理
→ 对外提供 API
→ 按 token / QPS / GPU 小时计费
```

这对算力中心很重要，因为训练是阶段性需求，推理是长期需求。

**6. 行业模型共建**
算力中心有行业客户资源，比如政务、金融、制造、医疗。模型公司有模型能力。双方一起做行业模型。

```text
行业数据
+ 模型公司微调能力
+ 算力中心基础设施
= 行业专用模型
```

例如：

```text
政务大模型
医疗问诊模型
工业质检模型
金融投研模型
教育批改模型
```

**双方各自想要什么**

算力中心想要：

```text
GPU 利用率
长期租约
标杆客户
模型应用落地
政府/产业项目背书
```

模型公司想要：

```text
低成本 GPU
稳定集群
云平台分发
企业客户入口
私有化交付能力
```

**典型收入结构**

```text
GPU 租赁费
API 调用费
模型授权费
私有部署费
微调服务费
运维服务费
收入分成
联合解决方案项目费
```

**关键矛盾**

1. **算力中心怕 GPU 闲置**
   - 买了很多卡，但没有足够训练/推理任务。

2. **模型公司怕算力成本太高**
   - 训练和推理都烧钱，需要低价稳定资源。

3. **企业客户怕模型不落地**
   - 只买算力没有应用，只买模型没有部署能力。

所以最好的合作不是单纯租 GPU，而是：

```text
算力中心 + 模型公司 + 行业客户
```

三方闭环：

```text
算力中心提供基础设施
模型公司提供模型能力
行业客户提供场景和数据
最终形成可收费的 AI 应用
```

一句话总结：

**算力中心卖的是“AI 生产资料”，模型公司卖的是“AI 能力”，两者合作的目标是把 GPU 小时转化成模型 API、行业解决方案和企业自动化收入。**

3. **企业客户怕模型不落地**
   - 只买算力没有应用，只买模型没有部署能力。

所以最好的合作不是单纯租 GPU，而是：

```text
算力中心 + 模型公司 + 行业客户
```

三方闭环：

```text
算力中心提供基础设施
模型公司提供模型能力
行业客户提供场景和数据
最终形成可收费的 AI 应用
```

一句话总结：

**算力中心卖的是“AI 生产资料”，模型公司卖的是“AI 能力”，两者合作的目标是把 GPU 小时转化成模型 API、行业解决方案和企业自动化收入。**

## [ASSISTANT]
一般来说，**头部模型公司会自建一部分算力中心，但很少完全只靠自建**。更多是混合模式：

```text
自建核心算力
+ 租用云 GPU
+ 与云厂商/智算中心合作
+ 特定项目私有化部署
```

**为什么会自建**

1. **降低长期成本**
   - 训练和推理规模足够大时，长期租云 GPU 很贵。
   - 自建或长期包机可以摊薄成本。

2. **掌控训练节奏**
   - 大模型训练需要稳定集群、网络、存储、调度。
   - 如果总是排队租云，会影响研发节奏。

3. **保护核心资产**
   - 模型权重、训练数据、训练代码、RL 数据很敏感。
   - 自建环境更容易做安全隔离。

4. **优化系统效率**
   - 模型公司可以深度优化网络、通信、调度、推理引擎。
   - 比如 MoE 训练、长上下文推理、KV cache 管理，都需要底层工程配合。

**为什么不会完全自建**

1. **资本开支太重**
   - H100/H200/B200 集群、InfiniBand、存储、电力、冷却都很贵。
   - 一次建设可能就是数千万到数亿美元级别。

2. **需求波动大**
   - 训练是阶段性高峰，推理是持续负载。
   - 全部自建容易出现资源闲置或峰值不够。

3. **运维难度高**
   - 大规模 GPU 集群故障率、网络调优、作业调度、驱动版本、散热供电都很复杂。
   - 模型公司未必想把自己变成数据中心公司。

4. **地理和合规问题**
   - 不同国家/地区客户可能要求本地部署。
   - 只靠自建中心难覆盖所有市场。

**常见组合**

| 公司阶段 | 算力策略 |
|---|---|
| 初创模型公司 | 主要租云 GPU / 智算中心 |
| 成长期模型公司 | 长租 GPU + 云合作 + 小规模自建 |
| 头部模型公司 | 自建核心集群 + 云厂商战略合作 |
| 企业私有化项目 | 用客户或合作算力中心部署 |

**现实里的模式**

- OpenAI：深度绑定 Microsoft Azure。
- Anthropic：同时和 AWS、Google Cloud 合作。
- Google Gemini：主要依托 Google 自有 TPU/GPU 基础设施。
- Meta：大量自建/自持 GPU 集群。
- DeepSeek：更强调高效训练和低成本算力使用，但也需要稳定大规模集群。
- 国内模型公司：常见是自建一部分，同时用云厂商、地方智算中心、合作机房。

一句话：

**模型公司通常不会一开始就重资产自建完整算力中心；只有当训练和推理规模足够大、成本和安全变成核心问题时，才会自建核心集群，同时继续保留云和合作算力作为弹性资源。**
