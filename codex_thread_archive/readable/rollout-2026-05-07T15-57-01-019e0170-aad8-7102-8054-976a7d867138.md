# Escalation Requests

Commands are run outside the sandbox if they are approved by the user, or match an existing rule that allows it to run unrestricted. The command string is split into independent command segments at shell control operators, including but not limited to:

- Pipes: |
- Logical operators: &&, ||
- Command separators: ;
- Subshell boundaries: (...), $(...)

Each resulting segment is evaluated independently for sandbox restrictions and approval requirements.

Example:

git pull | tee output.txt

This is treated as two command segments:

["git", "pull"]

["tee", "output.txt"]

Commands that use more advanced shell features like redirection (>, >>, <), substitutions ($(...), ...), environment variables (FOO=bar), or wildcard patterns (*, ?) will not be evaluated against rules, to limit the scope of what an approved rule allows.

## How to request escalation

IMPORTANT: To request approval to execute a command that will require escalated privileges:

- Provide the `sandbox_permissions` parameter with the value `"require_escalated"`
- Include a short question asking the user if they want to allow the action in `justification` parameter. e.g. "Do you want to download and install dependencies for this project?"
- Optionally suggest a `prefix_rule` - this will be shown to the user with an option to persist the rule approval for future sessions.

If you run a command that is important to solving the user's query, but it fails because of sandboxing or with a likely sandbox-related network error (for example DNS/host resolution, registry/index access, or dependency download failure), rerun the command with "require_escalated". ALWAYS proceed to use the `justification` parameter - do not message the user before requesting approval for the command.

## [ASSISTANT]
可以注册，但关键不是“AI 生成”四个字，而是你能不能证明作品里有**人的独创性贡献**。

**核心判断**
在美国，官方口径是：纯 AI 自动生成、只靠 prompt 得到的内容通常不能作为版权登记；但如果人类作者决定了足够的表达元素，或对 AI 输出做了有创意的编排、改写、剪辑、混音、歌词、旋律、和声等贡献，可以登记这些“人类创作部分”。美国版权局 2025 年报告也明确说，单纯提供 prompts 不够，但 AI 辅助创作不当然排除版权保护。见 [U.S. Copyright Office AI 页面](https://www.copyright.gov/ai/) 和 [2025 Part 2 公告](https://www.copyright.gov/newsnet/2025/1060.html)。

**音乐要分两层登记**
1. **词曲版权 / musical work**：旋律、歌词、和声、编曲等。  
2. **录音版权 / sound recording**：最终录音、演唱、制作、混音母带等。  

美国版权局也强调，音乐作品和录音作品是两类不同权利；同一首歌的“词曲”和“录音”不是一回事。见 [Musical Compositions and Sound Recordings](https://www.copyright.gov/register/pa-sr.html)。

**AI 音乐实操建议**
如果你想提高登记成功率和日后维权能力，最好这样做：

1. 保留创作证据：歌词草稿、旋律 MIDI、工程文件、分轨、prompt 记录、版本修改记录、混音工程、发布日期。
2. 明确人的贡献：比如“本人创作歌词、选择和修改旋律结构、重编曲、剪辑 AI 生成片段、完成混音母带”。
3. 登记时不要把 AI 写成作者：作者应是自然人或公司/权利人；AI 工具不能当作者。
4. 如实披露 AI 参与：美国申请中要说明 AI 生成内容，并把不可版权保护的纯 AI 部分排除，只主张人类创作部分。
5. 检查 AI 平台条款：确认 Suno、Udio、Stable Audio 等是否允许商业使用、你是否拥有输出使用权。
6. 避免侵权风险：不要输入未授权歌词、采样、伴奏；不要模仿真实歌手声音或特定艺人风格到容易混淆的程度。

**在中国怎么做**
中国著作权登记是自愿登记，登记与否不影响著作权取得，但登记证书通常可作为权属初步证据。国家版权局《作品自愿登记试行办法》规定“作品不论是否登记，作者或其他著作权人依法取得的著作权不受影响”。见 [国家版权局文件](https://www.ncac.gov.cn/xxfb/flfg/bmgz/202410/P020241015603746503748.pdf)。

通常可通过中国版权保护中心或地方版权局办理。音乐类一般准备：

- 作品著作权登记申请表
- 身份证明或公司营业执照
- 权利归属证明
- 作品样本：音频、歌词、曲谱、工程说明等
- 作品说明书：创作意图、创作过程、独创性，建议写清 AI 只是工具，人的创作贡献在哪里

入口可从 [中国版权保护中心官网](https://www.ccopyright.com.cn/) 或登记系统办理；中国音乐家协会也整理过 CPCC 登记流程参考：[作品著作权登记介绍](https://www.chnmusic.org.cn/qybh/202304/t20230427_1278325.html)。

如何看待未来ai音乐的版权市场

## [ASSISTANT]
我觉得未来 AI 音乐版权市场不会简单变成“AI 音乐有没有版权”这一题，而会拆成几个更细的市场：**人类创作权、AI 输出使用权、训练数据授权、声音/声纹权、平台分发权、录音制作者权**。版权会从“一首歌归谁”变成“这首歌的每一层分别归谁”。

**我的判断**

AI 音乐会大量压低“背景音乐、短视频配乐、游戏占位音乐、广告 demo、小语种改编、情绪歌单”的制作成本。这部分市场会变得非常便宜，甚至接近订阅制素材库。普通 AI 生成音乐如果没有品牌、人设、艺人关系、场景流量，版权价值会被稀释。

但高价值版权不会消失，反而会更集中。真正值钱的会是：

1. **有真人创作痕迹的 AI 辅助音乐**  
   例如作曲人、制作人、歌手用 AI 做灵感、编曲、demo、混音，但最终作品有明确人的表达贡献。

2. **可证明权利链干净的音乐库**  
   未来品牌、影视、游戏公司会更在意“可商用、可追溯、无训练数据纠纷、无声纹侵权”的 AI 音乐。干净授权会变成溢价点。

3. **声音授权市场**  
   歌手、配音演员、虚拟艺人的声音模型会像字体、肖像、IP 一样授权。未来可能出现“某歌手授权声库”“某风格合法模型”“按使用量分成”的市场。

4. **个性化音乐版权**  
   每个用户、每个广告、每个游戏场景都生成不同音乐。传统“一首歌卖给很多人”的模式，会部分变成“生成系统 + 授权规则 + 分发结算”。

5. **数据和模型授权**  
   唱片公司、音乐版权方会把曲库变成训练授权资产。谁拥有高质量、可授权的数据，谁就可能在 AI 音乐产业链里继续收租。

**最大变化**

以前音乐版权市场的核心是：  
“谁写了这首歌，谁录了这首歌，谁发行了这首歌。”

未来会变成：  
“谁提供了训练数据，谁设计了生成系统，谁做了人的创作选择，谁拥有声音，谁承担侵权风险，谁控制分发场景。”

**风险也会变大**

最大的不确定性有三个：

- AI 生成作品在各国版权法下保护不一致；
- 训练数据是否侵权还会继续打官司；
- 模仿歌手声音、风格、歌词结构可能引发人格权、商标、不正当竞争或版权纠纷。

所以我会把未来 AI 音乐分成两类看：

**低价值 AI 音乐**：大量、便宜、可替代，像素材库。  
**高价值 AI 音乐**：有清晰人类创作、有干净授权链、有声音/IP/场景绑定，像新型版权资产。

我的结论是：AI 不会杀死音乐版权市场，但会让“普通音乐版权”贬值，让“可证明、可授权、可商业使用的音乐权利包”更值钱。未来真正赚钱的不是会生成音乐的人，而是能把 AI 音乐做成**合法、可控、可分发、可结算资产**的人。

**核心能力**
MiniMax 当前主推模型是 `music-2.6`，用于根据 `prompt` 和 `lyrics` 生成完整歌曲。`prompt` 控制风格、情绪、场景，比如 “Soulful Blues, Rainy Night”；`lyrics` 提供歌词内容。文档也说明，如果没有歌词，可以用 `lyrics_optimizer: true` 让系统根据 prompt 自动生成歌词。

对你前面关心的“乐器类 AI 音乐”，关键参数是：

```json
"is_instrumental": true
```

开启后可以生成**无 vocals 的纯器乐音乐**，这对版权商业化更友好，因为少了歌词和歌手声纹风险。

**音频输出**
接口是：

```text
POST https://api.minimax.io/v1/music_generation
```

输出可以选：

- `output_format: "hex"`：返回十六进制音频数据
- `output_format: "url"`：返回音频下载链接，但文档提醒 URL **24 小时后过期**

音频设置支持：

```json
"audio_setting": {
  "sample_rate": 44100,
  "bitrate": 256000,
  "format": "mp3"
}
```

所以实际保存文件时，最好立刻下载 URL，或把 hex 解码成本地 `.mp3` 文件。

**模型选择**
文档列出的模型包括：

- `music-2.6`：付费/Token Plan 用户，推荐，RPM 更高
- `music-2.6-free`：免费版本，RPM 更低
- `music-cover`：参考音频翻唱/改编
- `music-cover-free`：免费翻唱版本

Token Plan 页面还显示 Music-2.6 在套餐里是按每日 quota 计算，当前文档写的是 **100 songs/day，单首不超过 5 分钟**，并标注前 2 周免费。

**Cover 功能的版权风险更高**
`music-cover` 支持传入参考音频：

```json
{
  "model": "music-cover",
  "audio_url": "https://example.com/original-song.mp3",
  "prompt": "Jazz, smooth, late night lounge, saxophone"
}
```

它可以做一键 cover，也可以先调用：

```text
POST /v1/music_cover_preprocess
```

提取：

- `cover_feature_id`
- `formatted_lyrics`
- `structure_result`
- `audio_duration`

再修改歌词生成 cover。这里版权风险明显更高，因为 reference audio 可能涉及原词曲、录音、表演者权利。用于商业项目时，不建议拿未授权歌曲做 cover。

```json
{
  "model": "music-2.6",

  "audio_setting": {
    "sample_rate": 44100,
    "bitrate": 256000,
    "format": "mp3"
  },
  "output_format": "url"
}
```
