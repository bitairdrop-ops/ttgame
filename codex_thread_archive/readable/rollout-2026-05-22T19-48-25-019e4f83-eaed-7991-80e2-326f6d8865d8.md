# Escalation Requests

Commands are run outside the sandbox if they are approved by the user, or match an existing rule that allows it to run unrestricted. The command string is split into independent command segments at shell control operators, including but not limited to:

- Pipes: |
- Logical operators: &&, ||
- Command separators: ;
- Subshell boundaries: (...), $(...)

Each resulting segment is evaluated independently for sandbox restrictions and approval requirements.

Example:

git pull | tee output.txt

This is treated as two command segments:

["git", "pull"]

["tee", "output.txt"]

Commands that use more advanced shell features like redirection (>, >>, <), substitutions ($(...), ...), environment variables (FOO=bar), or wildcard patterns (*, ?) will not be evaluated against rules, to limit the scope of what an approved rule allows.

## [ASSISTANT]
在 Steam 上传游戏的核心流程是走 **Steamworks / Steam Direct**：

1. 注册 Steamworks 开发者账号  
   进入 [Steamworks Partner Program](https://partner.steamgames.com/steamdirect)，完成身份、公司/个人、银行、税务信息。

2. 支付 Steam Direct 费用  
   目前每个产品需要支付 **100 美元 Steam Direct Fee**。Steam 官方说明里还写着：付费后到游戏可正式发布之间有 **30 天等待期**。

3. 创建 App  
   在 Steamworks 后台创建你的游戏 App，拿到 `App ID`。之后要配置：
   - 商店页面
   - 游戏名称、简介、截图、视频
   - 价格、地区、标签
   - 支持语言
   - 系统需求
   - 成就、云存档、控制器支持等可选功能

4. 上传游戏 Build  
   上传方式主要是 **SteamPipe**。官方文档在这里：[Uploading to Steam](https://partner.steamgames.com/documentation/steampipe)。  
   一般流程是：
   - 下载 Steamworks SDK
   - 准备 Windows/macOS/Linux 的游戏可执行文件
   - 配置 Depot
   - 用 SteamPipe / SteamCMD 上传 Build
   - 在 Steamworks 后台把 Build 设为测试分支或默认分支

5. 配置启动项  
   很重要。Steam 需要知道点“开始游戏”时运行哪个 `.exe` / `.app` / Linux executable。  
   常见审核失败原因就是：Build 上传了，但 Launch Options 没配对，导致 Steam 客户端启动时报 “missing executable”。

6. 自己测试安装  
   用你的开发者 Steam 账号，在 Steam 客户端里安装并运行游戏。确认：
   - 能下载完整文件
   - 能从 Steam 启动
   - 存档路径正常
   - 分辨率、全屏、手柄、音频正常
   - 没有依赖缺失，比如 DLL、运行库、资源文件路径错误

7. 提交审核  
   Steam 有两个主要审核：
   - **商店页面审核**
   - **游戏 Build 审核**

   官方发布流程文档：[Release Process](https://partner.steamgames.com/documentation/releasing)

8. 通过后设置发布日期并发布  
   审核通过、30 天等待期结束、商店页面和 Build 都准备好后，就可以设置正式发布时间。

如果你是 Godot 游戏，最简单的准备方式是先导出：

- Windows: `.exe` + `.pck` 或内嵌 pck
- macOS: `.app`
- Linux: executable + `.pck`

然后把每个平台放到对应 Depot。你现在这些 Godot 项目如果要上 Steam，我建议先做 **Windows 版 Steam Build**，因为审核和玩家覆盖最直接。

func unlock_full_version():

        await get_tree().create_timer(3.0).timeout

            save_license_locally()
            unlock_content()

- webhook 必须校验签名。
- 后端必须校验金额、币种、订单 ID、收款地址。
- 每个订单只能解锁一次。
- device_id 只用于低成本授权，不要当作强身份。
- 本地 license 可以被破解，所以高价值内容应以后端状态为准。

**推荐第一版技术选型**
```text
Game: Godot
Backend: Node.js / Express
Database: SQLite 起步，后续 PostgreSQL
Payment: NOWPayments 或 Coinbase Commerce
Network: Polygon / BSC
Currency: USDT / USDC
Hosting: Cloudflare Workers / Render / Fly.io / Railway
```

**为什么第一版不用 UAccess 自动解锁**
UAccess 更适合“付款后下载文件”，不适合直接把支付成功状态推给 Godot。它可以作为手动 license code 方案，但如果要自动解锁，最好用自己的 checkout + 后端订单系统。

**上线顺序**
1. 做 Godot 内 `Unlock Full Version` 按钮。
2. 后端实现订单表和 `POST /api/orders`。
3. 接入一个支付网关 checkout。
4. 实现 webhook，把订单改成 `paid`。
5. Godot 每 3 秒查询订单状态。
6. paid 后写入本地 license 并解锁。
7. 上线前做小额真实支付测试。

**产品判断**
这套方案适合：
- itch.io 免费 Demo
- 自己网站/checkout 收加密货币
- PC 完整版解锁
- 小额一次性购买

不适合：
- Steam 版本
- App Store / Google Play 内购替代
- 强监管地区的大规模商业发行
- 高投机 NFT/GameFi 玩法

建议第一版目标很窄：**只做一次性购买完整版自动解锁**。等这条链路跑通，再考虑钱包账号、NFT 收藏品或多商品商城。

function pay(bytes32 orderId) external payable {
    require(msg.value == PRICE, "wrong amount");
    require(!paidOrders[orderId], "already paid");

    paidOrders[orderId] = true;

    emit PaymentReceived(orderId, msg.sender, msg.value);
}

```solidity
function pay(bytes32 orderId) external {
    require(!paidOrders[orderId], "already paid");

    token.transferFrom(msg.sender, treasury, PRICE);

    paidOrders[orderId] = true;

    emit PaymentReceived(orderId, msg.sender, PRICE);

```

- GMV $20M，按 8%-10% 抽成，平台收入约 $1.6M-$2M
- GMV $50M，平台收入约 $4M-$5M
- GMV $100M，平台收入约 $8M-$10M

但 itch.io 没公开 GMV，所以只能估算。

不要太信一些“网站估值器”：例如 Hypestat 估 itch.io 如果靠广告可有约 **$12.1M 年收入**、约 **$37.5M 净值**；WorthOfWeb 甚至给到 **$20.3M 年收入 / $361M 估值**。这些页面自己也说明是按流量和广告潜力估算，不等于 itch.io 实际平台收入。来源：[Hypestat](https://hypestat.com/info/itch.io)、[WorthOfWeb](https://www.worthofweb.com/website-value/itch.io/)

商业上我的判断：itch.io 的价值主要在 **独立游戏社区、长尾内容库、Game Jam/实验游戏入口、创作者关系**，但收入能力和支付稳定性弱于 Steam。2025 年还出现过开发者 payout 延迟报道，这会压低投资人或收购方给它的估值倍数。来源：[GameDeveloper](https://www.gamedeveloper.com/business/developers-report-delayed-payouts-from-itch-io)

DMCA 是 **Digital Millennium Copyright Act**，中文通常叫 **美国数字千年版权法**。

在游戏平台里，你可以把 DMCA 理解成一个“版权下架流程”：

1. 有人把你的游戏、音乐、美术、代码、角色盗传到 Steam / itch.io / YouTube 等平台。
2. 你作为版权方提交 DMCA 投诉，说明：

   - 哪个作品是你的
   - 侵权链接在哪里
   - 为什么它侵权

3. 平台收到有效投诉后，通常会先把内容下架或禁用访问。
4. 上传者如果认为被误伤，可以提交反通知。
5. 如果双方继续争议，就要走法律程序。

- **保护你**：别人盗传你的游戏，你可以用 DMCA 要求下架。
