[49] assistant: 要把音乐生成 API 封装成“大量用户并发生成歌曲”的产品，核心不是直接前端调 MiniMax，而是做一个**异步任务队列系统**：用户提交任务，你排队、限流、调用上游、存储结果、通知用户。

**推荐架构**

```text
Web / App
  ↓
你的后端 API
  ↓
鉴权、额度、风控、参数校验
  ↓
任务表 Job DB
  ↓
队列 Queue
  ↓
Worker 集群
  ↓
MiniMax / ElevenLabs / 其他音乐 API
  ↓
对象存储 S3/R2/OSS
  ↓
生成结果回写 DB
  ↓
前端轮询 / WebSocket / Push 通知
```

**不要同步等待生成**

音乐生成通常几十秒到几分钟。前端请求不要一直挂着等结果，应该这样：

1. 用户点击生成
2. 后端创建 `job_id`
3. 立即返回：

```json
{
  "job_id": "song_123",
  "status": "queued"
}
```

4. Worker 后台生成
5. 前端轮询：

```http
GET /api/music/jobs/song_123
```

6. 完成后返回：

```json
{
  "status": "completed",
  "audio_url": "https://cdn.example.com/song_123.mp3"
}
```

**关键模块**

1. **任务队列**

常见选择：

- Redis + BullMQ：Node.js 最方便
- Celery + Redis/RabbitMQ：Python 常见
- Sidekiq：Ruby
- Cloud Tasks / SQS / PubSub：云原生

如果你做 Node/Next.js，我建议：

```text
Next.js / Express API
+ PostgreSQL
+ Redis
+ BullMQ
+ Worker
+ S3/R2
```

2. **并发控制**

你需要控制三层并发：

```text
用户级并发：每个用户同时最多生成 N 首
全局并发：整个系统同时最多跑 M 个任务
上游并发：MiniMax API 同时最多请求 K 个
```

比如：

```text
free 用户：同时 1 个任务
pro 用户：同时 3 个任务
global worker concurrency：20
MiniMax provider concurrency：10
```

3. **额度与计费**

每次生成前先扣额度，失败再退回，或者先冻结额度。

```text
queued      创建任务，冻结 1 credit
processing 任务开始
completed  扣除 credit
failed     退回 credit
```

任务状态建议：

```text
queued
processing
succeeded
failed
canceled
expired
```

4. **多供应商封装**

不要把业务代码直接写死 MiniMax。做一个 provider 层：

```ts
interface MusicProvider {
  generate(input: GenerateMusicInput): Promise<GenerateMusicResult>
}
```

然后实现：

```text
MiniMaxProvider
ElevenLabsProvider
MubertProvider
FallbackProvider
```

这样以后可以：

- MiniMax 做主生成
- ElevenLabs 做高质量套餐
- Mubert 做 BGM
- 某个 API 超时后切备用
- A/B 测试不同模型

5. **结果存储**

不要长期依赖 MiniMax 返回的临时 URL。完成后立刻下载音频，上传到你自己的对象存储：

```text
MiniMax URL
-> Worker 下载
-> S3 / Cloudflare R2 / 阿里云 OSS
-> CDN URL
```

同时存：

```text
audio_url
duration
format
size
prompt
lyrics
provider
model
cost
seed / request_id
```

6. **失败重试**

音乐 API 可能超时、限流、返回空音频。建议：

```text
429 限流：指数退避重试
5xx：重试 2-3 次
4xx 参数错误：不重试
超时：标记 retryable
```

但要避免重复扣费。每个任务要有：

```text
idempotency_key
provider_request_id
attempt_count
last_error
```
