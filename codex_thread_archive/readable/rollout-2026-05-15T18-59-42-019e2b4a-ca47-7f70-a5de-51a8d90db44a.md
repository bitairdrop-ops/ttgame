# Escalation Requests

Commands are run outside the sandbox if they are approved by the user, or match an existing rule that allows it to run unrestricted. The command string is split into independent command segments at shell control operators, including but not limited to:

- Pipes: |
- Logical operators: &&, ||
- Command separators: ;
- Subshell boundaries: (...), $(...)

Each resulting segment is evaluated independently for sandbox restrictions and approval requirements.

Example:

git pull | tee output.txt

This is treated as two command segments:

["git", "pull"]

["tee", "output.txt"]

Commands that use more advanced shell features like redirection (>, >>, <), substitutions ($(...), ...), environment variables (FOO=bar), or wildcard patterns (*, ?) will not be evaluated against rules, to limit the scope of what an approved rule allows.

**用户主流程**
1. 首次打开 App。

5. 聊天模式：直接对话、提问、写方案、分析需求。
6. 代码模式：选择本地 workspace，AI 读取文件上下文，回答代码问题或生成修改方案。

**安全边界**

2. 默认不上传整个 workspace，只上传用户当前选择的文件或必要摘要。
3. 写文件前展示 diff。
4. 执行命令前展示命令、目录、风险说明。

第一步：生成大纲

**App 需要做校验**
DeepSeek 返回后不要马上生成 PPT，先检查：

- 是否是合法 JSON
- 是否有 `title`
- `slides` 是否存在
- 页数是否在 3-8 页之间
- 每页是否有 `title`
- 每页 bullets 是否不超过 5 条
- 每条 bullet 是否不超过 30-40 字
- 是否有 `speakerNotes`
- 是否包含儿童不适合内容
- 是否没有真实姓名、学校、电话等隐私字段

如果不合格，App 自动发第二次请求：

```text
你刚才的 JSON 不符合要求。
问题：
1. 第 2 页 bullets 太长
2. 第 4 页缺少 speakerNotes
请只返回修正后的 JSON，不要解释。
```

**推荐的 DeepSeek system prompt**
PPT 模式里可以单独使用更强约束：

```text
你是儿童教育 PPT 内容策划师。
你只输出严格 JSON，不输出 Markdown，不输出解释。
目标是生成适合小学生展示的 PPT 内容。

规则：
1. 每页只表达一个核心观点
2. 每页标题不超过 18 个中文字符
3. 每页 bullet 3-5 条
4. 每条 bullet 不超过 28 个中文字符
5. 必须包含 speakerNotes
6. 必须包含 visual
7. 内容适合 6-12 岁儿童

9. 不得输出代码块
10. 输出必须能被 JSON.parse 解析
```

**更稳的三段式**
如果要效果更好，可以三段：

```text
第一步：生成大纲
第二步：扩展成结构化 slide JSON
第三步：质量检查并修正
```

具体链路：

1. **Outline Pass**
   - 生成 5 页标题
   - 确定故事线
   - 不生成 PPT

2. **Slide Spec Pass**
   - 按固定 schema 输出 JSON
   - 每页带 layout、title、bullets、visual、speakerNotes

3. **Critic Pass**
   - 检查是否像儿童课堂 PPT
   - 检查是否过长、重复、抽象
   - 返回修正版 JSON

最后才交给本地 PPT runner。

**关键点**
DeepSeek 不应该直接“做 PPT 文件”。它只负责生成：

```text
结构化 PPT 内容
```

真正生成 PPT 的工作由：

```text
App + presentations-premium + artifact-tool
```

完成。

所以正确分工是：

| 角色 | 负责什么 |
|---|---|
| DeepSeek | 内容规划、结构化 JSON、讲稿 |
| App | 校验、重试、保存、链接展示 |
| PPT skill | 页面代码生成、布局、导出 PPTX |
| artifact-tool | 真正生成 PowerPoint 文件 |

**结论**
完全可行。下一步应该改 PPT 模块的生成流程，不是简单把 DeepSeek 回复转 PPT，而是让 DeepSeek 输出严格 slide spec，并在 App 里做 JSON 校验和自动修正。这样 PPT 内容质量会稳定很多。
