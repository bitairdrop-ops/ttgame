# Escalation Requests

Commands are run outside the sandbox if they are approved by the user, or match an existing rule that allows it to run unrestricted. The command string is split into independent command segments at shell control operators, including but not limited to:

- Pipes: |
- Logical operators: &&, ||
- Command separators: ;
- Subshell boundaries: (...), $(...)

Each resulting segment is evaluated independently for sandbox restrictions and approval requirements.

Example:

git pull | tee output.txt

This is treated as two command segments:

["git", "pull"]

["tee", "output.txt"]

Commands that use more advanced shell features like redirection (>, >>, <), substitutions ($(...), ...), environment variables (FOO=bar), or wildcard patterns (*, ?) will not be evaluated against rules, to limit the scope of what an approved rule allows.

## [ASSISTANT]
《隐形守护者》的玩法本质不是传统“动作游戏”，而是 **真人影像 + 剧情分支 + 选择后果 + 多结局收集** 的互动叙事产品。它更接近“可玩的谍战剧”。

**1. 核心玩法循环**

玩家扮演抗战时期的卧底肖途，在不同势力之间周旋。每一章由真人拍摄的剧情片段推进，中间穿插关键选择：

```text
观看剧情 -> 做选择 -> 改变人物关系/生死/路线 -> 进入新剧情 -> 解锁结局或死亡线 -> 回溯重选
```

它的“游戏性”主要来自三件事：

- **选择压力**：玩家不是选“好坏”，而是在身份暴露、信任、牺牲、阵营利益之间做取舍。
- **分支探索**：很多选择会导致失败、死亡、隐藏路线或不同结局。
- **回溯补完**：玩家会反复回到关键节点，尝试另一条支线，补全人物命运和真相。

公开资料也把它定位为“长篇真人互动影像体验”；Steam 页面描述它是橙光授权改编的真人互动影像作品。来源：[Steam 商店页](https://store.steampowered.com/app/998940)、[SteamDB](https://steamdb.info/app/998940/info/)。

**2. 它为什么不像普通互动电影那么无聊**

关键在于它把“选择”放进了高压谍战结构里。

普通互动影像容易变成“点选下一段视频”，但《隐形守护者》的选择常常有强后果：站队、隐瞒、背叛、救人、牺牲、保命。玩家不是单纯看剧情，而是在不断判断：

- 我现在应该讨好谁？
- 哪句话会暴露身份？
- 救这个人会不会害死更多人？
- 当前选择是短期安全，还是长期失败？

所以它的互动不是操作层面的，而是 **道德、情报、关系和生存判断** 层面的。

**3. 结构上更像“章节制分支剧”**

它不是开放世界，而是章节推进。每章有明确剧情目标，分支大多围绕关键节点展开。

可以抽象成：

```text
主线骨架：固定历史/谍战大剧情
分支节点：玩家选择改变局部走向
失败节点：错误选择导致死亡或任务失败
人物线：不同角色的信任、关系、命运变化
结局线：多路线、多结局、多补完
```

这种结构的好处是制作可控：主线可以保证戏剧张力，分支又给玩家参与感。坏处是自由度其实有限，玩家最终是在作者设计好的树状剧情里探索。

**4. 影像表现方式：低成本但高沉浸**

《隐形守护者》并不是大规模动态影视剧，它大量使用真人表演、实景拍摄、高清图片、配音和后期剪辑来构成体验。国金证券的行业点评提到，它以“高清图片+实时语音”的方式提供真实感和代入感，并认为它是“可以玩的影视剧”和“具备影视感染力的游戏”。来源：[国金证券行业点评 PDF](https://pdf.dfcfw.com/pdf/H3_AP201906041333584850_1.pdf)。

这说明它的制作模型很聪明：

- 不追求 3A 游戏的实时渲染。
- 不追求传统电视剧的大规模连续视频。
- 用真人影像解决角色真实感。
- 用分支剧本解决互动感。
- 用配音、音乐、剪辑强化情绪。

**5. 商业模式也很重要**

它采用买断制 + 后续章节/DLC + 角色鲜花等轻付费。中原证券报告提到，《隐形守护者》采用二段买断式收费，前 1-5 章首次付费，6-10 章以 DLC 形式购买，同时有鲜花支持角色的内置消费。来源：[中原证券报告 PDF](https://pdf.dfcfw.com/pdf/H3_AP201907051337785787_1.pdf)。

这类产品的商业优势是：

- 制作成本低于大型剧集和重度游戏。
- 对轻度玩家门槛低。
- 适合 Steam、WeGame、移动端等多平台发行。
- 可用剧情口碑带动传播。
- 演员不一定要大牌，关键是角色适配和剧本强度。

**6. 成功关键**

《隐形守护者》的模式可以总结为四个核心：

1. **强剧本先行**  
   它不是靠玩法复杂取胜，而是靠剧本、人物、反转、情绪记忆点取胜。

2. **真人影像提升代入感**  
   相比纯文字或二次元立绘，真人表演让谍战、牺牲、背叛更有现实感。

3. **选择必须有代价**  
   如果选择只是换几句台词，玩家很快会失去兴趣。它的许多选择会带来死亡、路线锁定或人物命运变化。

4. **分支服务主线，而不是摊大饼**  
   它没有做成完全开放叙事，而是用强主线控制节奏，用分支制造参与感。

**7. 对影游互动类游戏的启发**

如果要借鉴《隐形守护者》，重点不是“拍真人视频”本身，而是这个公式：

```text
强类型故事 + 高压选择 + 明确人物关系 + 可回溯分支 + 多结局收集 + 低门槛操作
```

适合的题材包括：

- 谍战
- 悬疑推理
- 恋爱修罗场
- 职场权谋
- 犯罪调查
- 末日生存
- 法庭辩论
- 偶像/娱乐圈养成

不适合的题材是高度依赖动作操作、物理战斗、开放探索的类型。因为这类影游互动的优势在“选择与剧情”，不是“手感与系统深度”。

一句话概括：  
**《隐形守护者》的玩法模式是用游戏的分支选择机制，把一部强情节真人谍战剧改造成可反复探索、可讨论、可补完的互动叙事产品。**

它采用买断制 + 后续章节/DLC + 角色鲜花等轻付费。中原证券报告提到，《隐形守护者》采用二段买断式收费，前 1-5 章首次付费，6-10 章以 DLC 形式购买，同时有鲜花支持角色的内置消费。来源：[中原证券报告 PDF](https://pdf.dfcfw.com/pdf/H3_AP201907051337785787_1.pdf)。

这类产品的商业优势是：

- 制作成本低于大型剧集和重度游戏。
- 对轻度玩家门槛低。
- 适合 Steam、WeGame、移动端等多平台发行。
- 可用剧情口碑带动传播。
- 演员不一定要大牌，关键是角色适配和剧本强度。

**6. 成功关键**

《隐形守护者》的模式可以总结为四个核心：

1. **强剧本先行**  
   它不是靠玩法复杂取胜，而是靠剧本、人物、反转、情绪记忆点取胜。

2. **真人影像提升代入感**  
   相比纯文字或二次元立绘，真人表演让谍战、牺牲、背叛更有现实感。

3. **选择必须有代价**  
   如果选择只是换几句台词，玩家很快会失去兴趣。它的许多选择会带来死亡、路线锁定或人物命运变化。

4. **分支服务主线，而不是摊大饼**  
   它没有做成完全开放叙事，而是用强主线控制节奏，用分支制造参与感。

**7. 对影游互动类游戏的启发**

如果要借鉴《隐形守护者》，重点不是“拍真人视频”本身，而是这个公式：

```text
强类型故事 + 高压选择 + 明确人物关系 + 可回溯分支 + 多结局收集 + 低门槛操作
```

适合的题材包括：

- 谍战
- 悬疑推理
- 恋爱修罗场
- 职场权谋
- 犯罪调查
- 末日生存
- 法庭辩论
- 偶像/娱乐圈养成

不适合的题材是高度依赖动作操作、物理战斗、开放探索的类型。因为这类影游互动的优势在“选择与剧情”，不是“手感与系统深度”。

一句话概括：  
**《隐形守护者》的玩法模式是用游戏的分支选择机制，把一部强情节真人谍战剧改造成可反复探索、可讨论、可补完的互动叙事产品。**

政府封锁剧场，观众、演员、镇长、神父、外卖员、退休宇航员、网红阴谋论者全部被困。情报显示：外星人已经伪装成其中一名人类，并且正在学习人类行为。

问题是：这里每个人看起来都不像正常人。

**主要角色**

1. **玩家 / 调查员**
   - 被误认为“联邦外星事务局专家”
   - 实际上只是路过剧场的普通人
   - 通过选择推动剧情

2. **镇长 Bob**
   - 永远把灾难包装成旅游项目
   - 口头禅：“This is great for local business.”
   - 可疑点：对外星飞船态度过于兴奋

3. **剧场导演 Linda**
   - 把所有危机都当成“即兴戏剧训练”
   - 坚持每个人必须“演出真实的恐惧”
   - 可疑点：知道太多奇怪的宇宙术语

4. **退休宇航员 Frank**
   - 自称去过月球，但没人相信
   - 每句话都像酒吧吹牛
   - 可疑点：他真的可能见过外星人

5. **阴谋论网红 Kyle**
   - 坚信所有人都是外星人，除了他自己
   - 直播标题：“I WAS RIGHT AGAIN”
   - 可疑点：越懂外星人越像外星人

6. **外卖员 Maria**
   - 只是来送披萨，却被困进调查
   - 情绪最稳定，反而最可疑
   - 可疑点：她能记住所有人的订单，包括外星飞船的

7. **神父 Patrick**
   - 试图给外星人做灵魂辅导
   - 经常把科幻问题变成宗教辩论
   - 可疑点：他对“非地球生命”接受得太快

8. **儿童剧演员 Tommy**
   - 正在扮演一棵树
   - 全程不肯脱树服
   - 可疑点：树知道得太多

**第一幕：飞船坠落之夜**  
剧场演出刚开始，屋顶被砸穿。所有人以为这是导演安排的沉浸式演出。玩家第一次选择相信谁，并决定先调查哪组角色。

**第二幕：人类常识测试**  
玩家设计一系列测试找出外星人：

- 让嫌疑人解释什么是“small talk”
- 让他们假装在电梯里遇到邻居

- 让他们讲一个正常的人类笑话
- 让他们解释为什么人类会买健身卡但不去健身房

外星人不一定答错，因为人类本身也很荒唐。

**第三幕：剧场审判**  
所有角色必须在舞台上重演“自己今天最像人类的一刻”。  
玩家可以打断、追问、换剧本、安排角色互相对质。

**第四幕：指认外星人**  
玩家基于证据选择一名嫌疑人。不同选择进入不同结局。

**第五幕：真相反转**  
外星人的目标不是侵略地球，而是完成一篇宇宙社会学论文：  
《为什么人类明明讨厌开会，却不断发明新的会议形式》。

可疑度

玩家不能只看“奇怪”，因为最奇怪的人可能只是普通美国小镇居民。

序章：飞船砸进剧场
  -> 第一幕：封锁剧场，确认嫌疑人
  -> 第二幕：分组调查，收集异常证据

玩家需要在一夜之内找出伪装成人类的外星人。

**序章：屋顶事件**

年度小镇剧场节正在上演《人类文明的伟大时刻》。

突然，一艘小型飞船砸穿剧场屋顶。

玩家可做第一次选择：

```text
A. 相信这是外星事件
B. 认为是导演的沉浸式演出
C. 怀疑镇长在搞旅游营销
```

影响：

- A：进入“严肃调查线”
- B：进入“剧场即兴线”
- C：进入“阴谋商业线”

---

**第一幕：嫌疑人登记**

所有人被困在剧场内。玩家需要选第一轮调查对象。

```text
分支1：调查镇长 Bob
分支2：调查导演 Linda
分支3：调查退休宇航员 Frank
分支4：调查外卖员 Maria
分支5：调查阴谋论网红 Kyle
分支6：调查树服演员 Tommy
```

每条线都会给出一条“可疑证据”和一条“搞笑反证”。

例：

```text
Bob 可疑：提前准备了外星旅游纪念品
Bob 反证：他只是任何灾难都想卖票

Tommy 可疑：树服里藏着发光装置
Tommy 反证：那是儿童剧廉价灯带
```

**第二幕：人类常识测试**

玩家设计测试，观察角色反应。

**测试分支 A：社交寒暄测试**

问题：  
“当别人问 How are you，你应该怎么回答？”

结果：

```text
回答“Fine, thanks.” -> 像人类
认真讲20分钟心理状态 -> 可疑但可能只是美国人太需要心理咨询
反问“为什么你询问但不想知道答案？” -> 外星嫌疑上升
```

**测试分支 B：食物测试**

让嫌疑人吃披萨。

```text
喜欢菠萝披萨 -> 引发全场争吵
用刀叉精确切成八边形 -> 外星嫌疑上升
声称披萨是“人类圆形营养飞盘” -> 高危证据
```

**测试分支 C：笑话测试**

让嫌疑人讲一个人类笑话。

```text
讲 dad joke -> 人类度上升
讲税务局笑话 -> 美国人类度上升
笑点完全基于碳基生命消亡 -> 外星嫌疑上升
```

```

```

最像人类的人反而最可疑，因为他模仿得太标准。

所有人表演“如果我是外星人”。

Kyle 演得过于专业

Linda 设计了一个完全正确的入侵流程

Tommy 的树服突然接收到信号
```

```

可能转向：

玩家怀疑 Linda 把所有人当实验演员。

剧情发展：

```text
Linda 承认她早就想拍一部“真实恐惧喜剧”
她让所有人继续演
玩家发现她的剧本里写着尚未发生的台词
```

可能转向：

- Linda 是天才疯导演
- Linda 拿到了外星剧本
- Linda 是外星人观察人类戏剧的伪装身份

**分支三：宇航员旧案线**

玩家怀疑 Frank 早就见过外星人。

剧情发展：

```text

普通票：看飞船残骸

至尊票：被外星人轻微绑架体验
```

**推理误导**  
他提前准备了外星人周边，所以非常可疑。

如果你的项目是《谁把外星人带进了剧场》这种 **卡通剧照 + 角色对话 + 分支选择 + 证据推理 + 少量动画/短视频**，Godot 很合适。  
如果你要做《隐形守护者》那种大量真人视频片段连续播放的产品，Godot 能做，但不是最顺手的方案。

**Godot 适合的部分**

- 分支剧情树
- 角色好感/嫌疑值/证据卡
- 多结局回溯
- 舞台剧式场景切换
- UI 菜单、时间线、章节选择
- 轻量动画、镜头推拉、音效、字幕
- 桌面端、Android、iOS 导出

Godot 有 `VideoStreamPlayer` 节点支持视频播放，官方文档也明确用于播放 `VideoStream` 资源：[Godot VideoStreamPlayer](https://docs.godotengine.org/en/latest/classes/class_videostreamplayer.html)。所以技术上可以播放剧情视频。

**需要注意的限制**

Godot 的视频系统不是它最强的部分。它更像“游戏引擎里的视频播放节点”，不是专业互动视频引擎。大量真人影像项目会遇到：

- 视频格式和编码限制
- 大量视频资源包体很大
- 视频切换可能有黑屏/卡顿风险
- 字幕、多语言、跳转点要自己管理
- Web 端视频和音频限制更多
- 移动端需要重点测试性能和包体

Godot 官方 Web 导出文档也长期提醒 Web 平台存在限制：[Godot Web export](https://docs.godotengine.org/en/4.5/tutorials/export/exporting_for_web.html)。所以如果目标是网页端短剧互动，可能要谨慎。

**我建议的制作方式**

对这个“寻找外星人伪装者”的项目，最合适的是：

```text
Godot 做游戏壳和互动系统
+ 剧照/短动画/漫画式镜头做剧情推进
+ 少量关键节点用短视频
+ 所有分支、证据、嫌疑值、结局由 Godot 管
```

也就是不要一开始拍大量连续真人视频，而是做成：

```text
剧场场景图
角色立绘/表情
关键分支剧照
字幕对白
音效和旁白
选择按钮
证据卡
嫌疑值变化
结局图
```

这种形态非常适合 Godot，成本低，迭代快，也符合你现在这个西式卡通剧场风格。

**推荐技术结构**

```text
SceneManager：章节/场景切换
DialogueSystem：对白、角色表情、字幕
ChoiceSystem：玩家选择
EvidenceSystem：证据卡收集
SuspicionSystem：角色嫌疑值
TimelineLog：已看剧情和回溯
EndingResolver：结局判定
Gallery：剧照/分支/结局回看
```

剧情数据可以放 JSON，例如：

```json
{
  "scene_id": "pizza_test",
  "background": "pizza_test_still.png",
  "characters": ["Maria", "Kyle", "Hank"],
  "dialogue": [],
  "choices": [
    {
      "text": "检查披萨小票",
      "add_evidence": "impossible_delivery_coordinates",
      "next": "receipt_branch"
    }
  ]
}
```

**更现实的判断**

如果你要做 Steam/PC 独立游戏：Godot 适合。  
如果你要做 Android/iOS 剧情互动游戏：Godot 也适合，但要控制视频数量。  
如果你要做网页 H5 传播型互动短剧：优先考虑 Web 技术栈，Godot Web 不是最稳。  
如果你要做高规格真人互动电影：Unity 或自研 Web/Native 视频播放器可能更合适。

对你这个项目，我会建议用 Godot 做 **第一版可玩原型**：  
先用生成的角色图、剧照、对白和选择系统跑通 3 个分支、1 个误判结局、1 个正确结局。等玩法证明有趣，再决定是否升级真人拍摄。

## [ASSISTANT]
Web 版本互动剧情：**Godot 可以做，但我不建议作为首选**。

如果你的目标是“浏览器里点开就玩”的影游互动剧情，尤其是移动端 H5、社交传播、嵌入网页、快速加载，**Web 技术栈更适合**：

```text
React / Vue / Svelte
+ 状态机/剧情 JSON
+ HTML5 video / image / audio
+ 本地存档 localStorage / IndexedDB
+ Canvas 或 CSS 动画
```

Godot Web 更适合：

```text
2D小游戏
轻量互动叙事
桌面浏览器优先
少量图片、少量音频
不依赖大量真人视频
```

不太适合：

```text
大量高清剧情视频
移动端浏览器首发
微信/H5式传播
需要快速首屏加载
需要 SEO/分享卡片/网页支付/账号系统深度集成
```

原因很现实：

- Godot Web 导出是一个 WebAssembly 游戏包，启动比普通网页重。
- Godot Web 对服务器 headers、`SharedArrayBuffer`、跨源隔离可能有要求。
- 浏览器音频通常需要用户先点击才能播放。
- Godot 官方文档提醒 `VideoStreamPlayer` 在 Web 上性能较差。
- 大量视频和字幕分支，用原生 HTML5 video 管理更直接。
- 网页支付、登录、分享、埋点，用 Web 技术更顺。

官方参考：Godot Web 导出文档提到 Web 平台的跨源隔离、音频交互限制等问题；`VideoStreamPlayer` 文档也提示 Web 视频播放性能问题。  
[Godot Web Export](https://docs.godotengine.org/en/4.5/tutorials/export/exporting_for_web.html)  
[Godot VideoStreamPlayer](https://docs.godotengine.org/en/latest/classes/class_videostreamplayer.html)

我的建议是：

**如果做《谁把外星人带进了剧场》的 Web 版，首选 Web 技术，不选 Godot。**

推荐架构：

```text
Next.js / React
+ XState 或自写剧情状态机
+ 剧情节点 JSON
+ 图片/短视频资源 CDN
+ 证据卡系统
+ 嫌疑值系统
+ 分支回溯图
+ 多结局存档
```

剧情节点可以这样：

```json
{
  "id": "pizza_test",
  "sceneImage": "/stills/pizza-test.webp",
  "characters": ["Maria", "Kyle", "Hank"],
  "dialogue": [
    {
      "speaker": "Maria",
      "text": "我可以解释这张小票，但你们得先签收。"
    }
  ],
  "choices": [
    {
      "text": "检查不可能的配送坐标",
      "addEvidence": "impossible_delivery_coordinates",
      "suspicion": { "Maria": 2 },
      "next": "receipt_branch"
    },
    {
      "text": "让 Kyle 停止直播",
      "suspicion": { "Kyle": 1 },
      "next": "kyle_argument"
    }
  ]
}
```

如果你只是想快速做一个桌面试玩版或 Steam 版，Godot 很合适。  
如果你明确要 **Web 互动剧情产品**，尤其想以后接支付、账号、分享、数据分析和移动端传播，**直接用 Web 栈会更稳、更轻、更商业化**。
